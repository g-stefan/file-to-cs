# File to CS — Documentation

`file-to-cs` turns any file into **C/C++ source**, so its content can be
compiled into a library or executable instead of being read from disk at
run time. It is both:

- **a command line tool**, `file-to-cs`, run by the `make.prepare.js`
  scripts of the XYO projects (fabricare, quantum-script and its
  extensions) to embed JavaScript sources and other text files in C++
  code;
- **a C++ library**, namespace `XYO::FileToCS`, with the same conversions
  as functions (`fileToCpp`, `fileToCString`, `fileToCStringDirect`), and
  the tool itself as a class that can be embedded in another program
  (fabricare does, as `fileToCS(...)`).

Three output forms:

| Form | Command line | Output | Use it for |
|------|--------------|--------|------------|
| byte array | `--name=data` | `static const uint8_t data[]={0x89,0x50,...};` | binary files: images, fonts, archives |
| string array | `--name=text --is-string` | `static const char text[]={0x70,0x72,...,0x00};` | text used as a C string (scripts, templates), exact bytes |
| string literal | `--is-string-direct` | `"print(\"hi\");\n..."` | readable / diffable text, included inside an expression |

## Why it exists

A program that needs a script, a template, an icon or a default
configuration can read it from a file next to the executable, but then the
file must be installed, found and kept in step with the binary. Embedding
it in the source makes the executable self-contained. Doing that by hand
means escaping every byte; `file-to-cs` does it as a build step:

| Problem | What `file-to-cs` does |
|---------|------------------------|
| A file must ship inside the binary | writes it as a `static const` array or string literal to `#include` |
| Binary content (`0x00`, high bytes) can not go in a string literal safely | the array forms write every byte as `0xHH`, nothing is interpreted |
| A script must be passed as a `const char *` | `--is-string` appends the `0x00` terminator to the array |
| Escaping text by hand (`\"`, `\\`, `\n`, control bytes) | `--is-string-direct` escapes it with `String::encodeC` |
| Regenerating on every build forces a recompile of everything that includes it | `--touch=file` regenerates only when the input is newer than the output, then touches the `.cpp` that includes it |
| Several resources in one generated file | `--append` adds an array to an existing output |
| Long build command lines | `@file` response files |

## Concepts at a glance

| Need | Command line | Library |
|------|--------------|---------|
| Embed a binary file | `file-to-cs --name=logo --file-in=logo.png --file-out=Logo.Source.cpp` | `XYO::FileToCS::fileToCpp("logo", in, out, false, false)` |
| Embed a text file as a C string | `... --name=script --is-string` | `fileToCpp("script", in, out, false, true)` |
| Embed text as an escaped literal | `file-to-cs --file-in=a.txt --file-out=a.inc --is-string-direct` | `fileToCStringDirect(in, out)` |
| `static const char *name="...";` | | `fileToCString("name", in, out)` |
| Several arrays in one file | second and later calls with `--append` | `append = true` |
| Regenerate only when changed | `--touch=Library.cpp` | `Shell::compareLastWriteTime` yourself |
| Run the tool from your own program | | `XYO::FileToCS::Application::Application` (`file-to-cs.application.static`) |
